# Virtual Piano Studio：漸進式揭露改版＋手機自動橫向 實作計畫（v3）

## 目標體驗

1. **進站**：只看到一台完整的鋼琴，按任意琴鍵就能彈。
2. **彈幾下之後**：琴蓋輕輕掀一下又落回去，提示可以打開。這個提示只出現一次。
3. **打開琴蓋**：才看到四個功能：譜架、聲音、和弦、錄音。
4. **手機**：直向進站時是一張完整鋼琴畫面。點一下後，同時解鎖音訊並轉成橫向：
   - Android：全螢幕並鎖定橫向。
   - iPhone：用 CSS 把整個畫面轉 90 度（假橫向）。

## 原則

- 重用現有的 `PianoEngine`、`player`、`Piano`、`PianoLid`、`Visuals`、`store`，**不重寫引擎和播放器**。
- 不新增第三方依賴，維持靜態網站。
- **狀態切換一律用 `data-*` 屬性搭配 CSS**，不用條件渲染去掛載或卸載主要元件。轉向、開關琴蓋、旋轉都不能打斷播放，也不能讓五線譜重新排版。
- 不要修改 `site-publish/`。
- 測試指令：`npx vitest run --exclude "site-publish/**"`；建置：`npm run build`。

## 第 0 階段：iPhone 假橫向的技術驗證（需實機，由使用者執行）

在 iPhone 實機上驗證：多點觸控與滑奏、`elementFromPoint` 判斷琴鍵、快速連打不卡音、彈奏時頁面不動、旋轉容器內的捲動方向、原生 range／select、安全區域、Safari 工具列伸縮、實際轉動手機播放不中斷。

決策點：原生控制項或捲動不能用 → 第 5 階段走「自訂控制項」路線（本計畫預設如此）。多點觸控或判斷琴鍵不能用 → 放棄假橫向，改提示「請橫放手機」。

## 第 1 階段：畫面狀態與資料結構

### 1.1 整個畫面只用三個狀態描述

| 狀態 | 值 | 說明 |
|---|---|---|
| `stage` | `"poster"`／`"playing"` | `poster`：手機直向的進站畫面，只有鋼琴和「點一下開始」。桌機直接從 `playing` 開始。 |
| `lidOpen` | `true`／`false` | 沿用現有的 `lidOpen` |
| `rotate` | `true`／`false` | 是否啟用 CSS 假橫向，由規則自動算出 |

把這三個狀態寫成 `.app` 上的 `data-stage`、`data-lid`、`data-rotate` 屬性，CSS 根據屬性決定版面。

### 1.2 什麼時候旋轉

`rotate = 觸控裝置 && 直向 && stage === "playing" && 沒有成功鎖定橫向`

- 觸控裝置：`(hover: none) and (pointer: coarse)`。
- 直向：`matchMedia("(orientation: portrait)")` 監聽。手機真的轉成橫向時 `rotate` 自動變 `false`；轉回直向又自動旋轉。
- 寫成 `useStageOrientation()` hook 集中管理。

### 1.3 移除「演奏版面／看譜版面」

- 拿掉 `mobileLayout` 切換列，改成「琴蓋關＝演奏，琴蓋開＝看譜和工具」。
- `store` 升到 version 4：migrate 移除 `mobileLayout`，新增 `lidHintSeen: boolean`。補移轉測試。
- `splitRatio` 保留，改成控制「琴蓋打開時工具區和琴鍵的高度比例」。

### 1.4 移除頁首選單

- 頁首的「鍵盤設定／音訊設定／琴蓋選單／曲目與工具」拿掉，功能都移進琴蓋。
- 常駐只留：右上角音源狀態點、全螢幕或離開按鈕。

**驗收**：狀態切換不會呼叫 `player.stop()`；store 移轉測試通過；桌機琴蓋開關功能和現在一樣。

## 第 2 階段：進站只見鋼琴

### 2.1 桌機
- 首屏只有完整的鋼琴：琴身、闔上的琴蓋、琴鍵，加一句「按任意琴鍵開始彈奏」。
- 和弦面板、播放列、練習區、頁尾都不顯示（條件見第 4 階段）。
- 琴鍵淡淡顯示電腦鍵盤字母（維持 `.key-binding`）。

### 2.2 手機直向（`stage="poster"`）
- 鋼琴畫面佔滿螢幕，中間大按鈕「點一下開始彈奏」，下面小字「將轉為橫向」。
- 點下去的同一次觸控裡依序：
  1. `engine.ready()` 解鎖音訊並開始下載取樣。
  2. Android：`requestFullscreen()` 成功後 `screen.orientation.lock("landscape")`；任何一步失敗退回 CSS 旋轉。
  3. iPhone：直接 `stage = "playing"`，`rotate` 自動變 `true`。
- 這個畫面的琴鍵按下去也視同按了「開始」。

### 2.3 琴鍵預設位置
- 預設以中央 C4 為中心（手機橫向目前從 C2 開始，要修正）。
- 手機橫向約顯示 12 個白鍵。八度 ‹ › 放在鍵盤左右兩端側板，至少 44×44px。

**驗收**：桌機首屏無捲軸只見鋼琴；手機直向首屏只有鋼琴和一個按鈕；載入期間狀態點顯示「載入中」。

## 第 3 階段：琴蓋提示（只出現一次）

- 觸發：`lidHintSeen === false`，且第一個音之後已彈 3 個音或過了 5 秒（先到為準）。
- 動作：琴蓋用現有彈簧動畫掀起約 15 度再落回，間隔約 1.5 秒，做兩次；同時顯示金色提示「掀開琴蓋，看看裡面有什麼」，指向琴蓋把手。
- 結束：打開琴蓋或點掉提示 → `lidHintSeen = true`，以後不再出現。
- `prefers-reduced-motion`：琴蓋不動，只顯示提示和靜態金色描邊。
- 手機橫向：琴蓋縮成頂部一條把手「︿ 琴蓋」，提示時把手往下彈一下；往下拉或點一下都能打開。

**驗收**：提示整個生命週期只出現一次；提示期間不擋琴鍵；補「提示只出現一次」的元件測試。

## 第 4 階段：琴蓋內容重組

### 4.1 四個分頁

| 分頁 | 內容 |
|---|---|
| 譜架 | 曲目（預設曲、小星星、匯入 MIDI／MusicXML、網址匯入）、Piano Roll／五線譜／琴譜、練習模式設定 |
| 聲音 | 四種風格、試聽、音量、殘響、力度、61／88 鍵 |
| 和弦 | 啟用開關、快速配置、一按保持、綁定模式 |
| 錄音 | 開始錄製、回放、匯出 MIDI |

- 觸控裝置上隱藏電腦鍵盤的鍵位設定。
- 分頁內不能再有第二層分頁。

### 4.2 什麼時候顯示

- 播放列：有曲子，且（琴蓋打開或正在播放）。琴蓋關上仍在播放時，留迷你播放列（播放／暫停、進度）。
- 和弦按鈕：「和弦」分頁啟用後才出現。桌機放在鍵盤左側，手機橫向放在鍵盤上方一排。
- 練習結果：只在練習模式播放時出現。
- 頁尾：只在桌機捲到最下面才看得到，手機不顯示。

### 4.3 琴蓋打開時的版面
- 桌機：琴蓋向上掀起，工具區在琴蓋和琴鍵之間，琴鍵始終看得到。
- 手機橫向：上半部工具區、下半部琴鍵，比例用 `splitRatio`，可拖曳。

**驗收**：所有現有功能在四個分頁裡都找得到（列「舊位置 → 新位置」對照表）；開關琴蓋不中斷播放和錄製；電腦鍵盤與一鍵和弦照常運作。

## 第 5 階段：iPhone CSS 假橫向

### 5.1 旋轉方式

```css
.app[data-rotate="true"] .stage {
  position: fixed;
  top: 0;
  left: 0;
  width: 100dvh;
  height: 100vw;
  transform-origin: top left;
  transform: translateX(100vw) rotate(90deg);
}
```

- 使用者把手機逆時針轉 90 度（頂部朝左）時畫面是正的；旁邊放小圖示提示轉向。
- `html`、`body`：`overflow: hidden`、`overscroll-behavior: none`。
- 舞台內不能有原生捲動，需要捲動的列表改成分頁或縮減內容。

### 5.2 觸控座標換算

新增 `toStage()`：`舞台 x = clientY`、`舞台 y = 螢幕寬度 − clientX`；`rotate=false` 原樣回傳。補四角與中心的單元測試。

要改的地方：
- 拖曳分隔條（App.tsx 的 splitter：用 `clientY`、`innerHeight`）→ 改用 `toStage()` 的 y 和舞台高度。
- Piano Roll 畫布尺寸（Visuals.tsx 的 `getBoundingClientRect()`）→ 改用 `offsetWidth`／`offsetHeight`。
- 五線譜游標自動捲動（Visuals.tsx 的 `getBoundingClientRect().top`）→ 改用 `offsetTop`。
- 琴鍵滑奏（Piano.tsx 的 `elementFromPoint`）不用改，但列入實機驗證。
- 全專案搜尋 `clientX|clientY|getBoundingClientRect|innerWidth|innerHeight` 逐一確認。

### 5.3 安全區域對調

| 舞台的邊 | 螢幕的邊 | 內距 |
|---|---|---|
| 左 | 上（瀏海） | `env(safe-area-inset-top)` |
| 右 | 下（Home 橫條） | `env(safe-area-inset-bottom)` |
| 上 | 右 | `env(safe-area-inset-right)` |
| 下 | 左 | `env(safe-area-inset-left)` |

在 `[data-rotate="true"]` 底下重新定義 `--safe-top/right/bottom/left`，元件只讀這四個變數。

### 5.4 原生控制項

| 類型 | 處理 |
|---|---|
| 滑桿（進度、音量、鍵盤位置） | 共用 `<StageSlider>`（Pointer Events＋`toStage()`），旋轉與否都用它 |
| 下拉選單（速度、轉調、練習類型、和弦配置） | 改成分段按鈕或 −／＋ 步進器 |
| 文字輸入（網址匯入） | 點下時暫時 `rotate=false`，顯示直向輸入面板，完成後轉回，顯示「已暫時轉回直向」 |
| 選擇檔案 | 不處理 |
| 勾選框 | 維持原生 |

### 5.5 Android
- 鎖定橫向成功：`rotate=false`。
- 離開全螢幕：監聽 `fullscreenchange`，解除鎖定、改用 CSS 旋轉，播放不中斷。

### 5.6 離開
- 右上角「離開」：解除鎖定、離開全螢幕、`stage="poster"`，播放狀態保留。

### 5.7 已知限制（寫進 README 常見問題）
- iPhone 狀態列、通知、控制中心仍是直向。
- Safari 網址列旋轉後在舞台右側；加入主畫面可隱藏。
- 系統鍵盤只以直向出現，打字時會暫時轉回直向。

**驗收**：拖曳分隔條、Piano Roll、五線譜游標旋轉後方向正確；瀏海與 Home 橫條不遮控制項。
